# IPC Protocol — Version 1 Baseline

**Status:** Contract proposal — **revision 2** (2026-10-22). The `.proto` files live in [`proto/`](../../proto/) of this repository and are finalized in M0.3. The sketches below mirror the current drafts in `proto/` (syntax-checked with `protoc`, not final); if they ever diverge, **`proto/` wins**.

## 1. Purpose and scope

One typed, versioned protocol family connects all components:

| Link | Transport | Services used |
|---|---|---|
| Web BFF → Gateway → Core | gRPC / TCP + mutual TLS (web→gateway), gRPC / UDS (gateway→core) | `postflowx.core.v1.*` |
| Core → Gateway → Plugin | gRPC / UDS | `postflowx.plugin.v1.PluginService` |
| Plugin → Gateway → Core | gRPC / UDS | `postflowx.host.v1.HostService` |
| Core ↔ Watchdog | gRPC / UDS | `postflowx.watchdog.v1.WatchdogControl` |
| Watchdog → every process | gRPC / UDS (health sockets) | `grpc.health.v1.Health` |

Request/response RPCs by default; server streaming only where a concrete need exists (media transfer, later events). No transport-specific assumptions in business modules.

## 2. Transport requirements

- Private networks/sockets only; nothing is published to the host except the web entry point.
- **Web ↔ server:** mutual TLS with an internal CA (generated by `scripts/init-secrets.sh`); server certificate SAN `server`; client certificate `CN=postflowx-web`. `production` mode refuses to start without mTLS.
- **Inside the server container:** Unix domain sockets under `/run/postflowx/`; access controlled by filesystem permissions (kernel-enforced), see ARCHITECTURE §2.
- **Health sockets:** every process serves the standard gRPC health protocol on `/run/postflowx/health/<name>.sock` (connectable by the Watchdog; returns serving status only, no details) so that health observation does not depend on the Gateway.
- Explicit request/response schemas in Protobuf; bounded message sizes; mandatory deadlines; correlation IDs; no public unauthenticated endpoint.

## 3. Identity and trust propagation

1. The **Gateway authenticates the transport**: mTLS certificate (web) or the plugin socket the call arrived on (plugin). It strips every client-supplied `x-pfx-*` metadata and sets:
   - `x-pfx-caller-kind`: `web | plugin | core`
   - `x-pfx-caller-id`: `postflowx-web | plugin:<id> | core`
   - `x-pfx-request-id`, `x-pfx-deadline-ms`
2. **Core accepts connections only on its socket** (accessible to the Gateway UID only) and trusts `x-pfx-caller-*` only because of that.
3. **User identity is never taken from a message field the caller controls:**
   - Web calls carry an opaque **session token** (metadata `x-pfx-session`); Core validates it and derives the actor.
   - Plugin calls carry a **call token** (field `ctx.call_token`) issued by Core for a Core-initiated call; Core checks it against the Gateway-assigned plugin identity.
4. Core makes the authorization decision on every operation: caller identity, capability/grant, actor, resource ownership, current state.

The Gateway is part of the trusted computing base (T13): it is small, holds no secrets other than its TLS key, and Core independently validates call tokens so a Gateway bug alone cannot grant cross-user access.

## 4. Gateway rules

- **Method allowlist per caller kind** (deny by default; unknown services/methods → `UNIMPLEMENTED`/`PERMISSION_DENIED`, logged):

| Caller kind | Allowed |
|---|---|
| `web` | `postflowx.core.v1.*` (Auth, Users, Plugins, Accounts, Media, Posts, Jobs, Health-read) |
| `plugin` | `postflowx.host.v1.HostService/*` only |
| `core` | `postflowx.plugin.v1.PluginService/*` toward the *named* plugin only |

- **Limits (defaults, configurable):** max message 4 MiB (media uses chunked streaming, 64 KiB chunks); max unary deadline 30 s (interactive), 120 s default / 10 min max for `Publish`; per-caller and per-plugin concurrency and rate limits; max metadata size.
- **Does not** parse business payloads (if generic proxying passes the M0.2 spike) and **does not** make authorization decisions beyond the method allowlist and limits.
- Fail closed: invalid/missing identity, unsupported protocol major version or malformed metadata → rejected.

## 5. Versioning

- Protobuf package carries the major version: `postflowx.core.v1`, `postflowx.host.v1`, `postflowx.plugin.v1`, `postflowx.watchdog.v1`, `postflowx.common.v1`.
- **Compatible changes** (new optional fields, new RPCs, new enum values with safe defaults) are additive; `buf breaking` in CI enforces this. Breaking change = new package `v2` served in parallel for one release.
- Plugins declare `api_compatibility` in the manifest; Core compares with its supported plugin API range at registration and refuses incompatible plugins (`INCOMPATIBLE`).
- Every service declares its supported range; unknown major versions fail closed. The contract version is the deploy-repo tag (`proto/` is versioned together with the release bundle), so contracts and component versions cannot drift apart.

package postflowx.common.v1;

// Passed by Core to a plugin and returned by the plugin on every user-scoped Host API call.

### 6.2 Plugin service (Core → plugin)

```proto
syntax = "proto3";
package postflowx.plugin.v1;

import "google/protobuf/duration.proto";
import "google/protobuf/struct.proto";
import "postflowx/common/v1/common.proto";

service PluginService {
  rpc Describe(DescribeRequest) returns (PluginDescriptor);
  rpc BeginConnect(BeginConnectRequest) returns (BeginConnectResponse);
  rpc HandleCallback(HandleCallbackRequest) returns (HandleCallbackResponse);
  rpc ValidatePost(ValidatePostRequest) returns (ValidatePostResponse);
  rpc Publish(PublishRequest) returns (PublishResponse);
  rpc Reconcile(ReconcileRequest) returns (ReconcileResponse);
  rpc RunTask(RunTaskRequest) returns (RunTaskResponse);
}

message DescribeRequest {}

enum ConnectFlow {
  CONNECT_FLOW_UNSPECIFIED = 0;
  CONNECT_FLOW_OAUTH2_REDIRECT = 1;
  CONNECT_FLOW_FORM = 2;
  CONNECT_FLOW_NONE = 3;
}

message MediaRules {
  repeated string allowed_mime_types = 1;
  int32 max_items = 2;
  int64 max_bytes_per_item = 3;
}

message PluginDescriptor {
  string plugin_id = 1;
  string version = 2;
  string api_version = 3;                        // e.g. "1.0"
  string display_name = 4;
  bytes icon_svg = 5;                            // size-limited, sanitized by Core
  ConnectFlow connect_flow = 6;
  google.protobuf.Struct settings_schema = 7;    // restricted JSON-Schema subset
  google.protobuf.Struct post_options_schema = 8;
  MediaRules media_rules = 9;
  int32 caption_max_length = 10;
}

message BeginConnectRequest {
  postflowx.common.v1.CallContext ctx = 1;
  string state = 2;         // generated and validated by Core
  string redirect_uri = 3;  // the BFF's generic callback URL
}
message BeginConnectResponse { string authorization_url = 1; }

message HandleCallbackRequest {
  postflowx.common.v1.CallContext ctx = 1;
  map<string, string> query = 2;  // provider callback parameters (untrusted)
}
message HandleCallbackResponse {
  string account_id = 1;
  string display_name = 2;
}

message MediaRef {
  string media_id = 1;
  string mime_type = 2;
  int64 size_bytes = 3;
}
message PostPayload {
  string caption = 1;
  repeated MediaRef media = 2;
  google.protobuf.Struct options = 3;  // validated against post_options_schema
}

message FieldIssue {
  string field = 1;
  string code = 2;
  string message = 3;  // safe for display
}
message ValidatePostRequest {
  postflowx.common.v1.CallContext ctx = 1;
  string account_id = 2;
  PostPayload post = 3;
}
message ValidatePostResponse { repeated FieldIssue issues = 1; }

enum Outcome {
  OUTCOME_UNSPECIFIED = 0;
  OUTCOME_PUBLISHED = 1;
  OUTCOME_RETRYABLE_FAILURE = 2;
  OUTCOME_RATE_LIMITED = 3;
  OUTCOME_AUTH_FAILURE = 4;
  OUTCOME_PERMANENT_FAILURE = 5;
  OUTCOME_UNKNOWN = 6;
}
message PublishRequest {
  postflowx.common.v1.CallContext ctx = 1;
  string job_id = 2;
  string attempt_id = 3;
  string idempotency_key = 4;
  string account_id = 5;
  PostPayload post = 6;
  bytes checkpoint = 7;  // opaque data the plugin stored via CheckpointAttempt in an earlier attempt
}
message PublishResponse {
  Outcome outcome = 1;
  string external_id = 2;
  string external_url = 3;
  string error_code = 4;     // stable, plugin-defined
  string error_message = 5;  // safe, user-presentable
  google.protobuf.Duration retry_after = 6;
}

enum ReconcileResult {
  RECONCILE_RESULT_UNSPECIFIED = 0;
  RECONCILE_RESULT_PUBLISHED = 1;
  RECONCILE_RESULT_NOT_PUBLISHED = 2;
  RECONCILE_RESULT_UNDECIDABLE = 3;
}
message ReconcileRequest {
  postflowx.common.v1.CallContext ctx = 1;
  string job_id = 2;
  string attempt_id = 3;
  string account_id = 4;
  PostPayload post = 5;
  bytes checkpoint = 6;
}
message ReconcileResponse {
  ReconcileResult result = 1;
  string external_id = 2;
  string external_url = 3;
}

message RunTaskRequest {
  postflowx.common.v1.CallContext ctx = 1;
  string task_name = 2;
  string account_id = 3;
}
message RunTaskResponse {
  bool ok = 1;
  string message = 2;
}
```

## 7. Errors

Standard gRPC status codes plus `google.rpc.ErrorInfo` (`domain = "postflowx"`, stable `reason`, optional `metadata`). No stack traces, SQL errors, secrets or internal paths to untrusted callers.

| gRPC status | `reason` examples | Meaning | Retryable? |
|---|---|---|---|
| `INVALID_ARGUMENT` | `VALIDATION_ERROR`, `INVALID_ENVELOPE` | payload/metadata invalid | no |
| `UNAUTHENTICATED` | `SESSION_INVALID`, `SERVICE_IDENTITY_UNKNOWN` | caller/session cannot be authenticated | no |
| `PERMISSION_DENIED` | `FORBIDDEN`, `CAPABILITY_NOT_GRANTED`, `CALL_TOKEN_INVALID` | authenticated but not allowed | no |
| `NOT_FOUND` | `NOT_FOUND` | absent **or intentionally hidden** | no |
| `ABORTED` / `FAILED_PRECONDITION` | `CONFLICT`, `VERSION_MISMATCH`, `STATE_INVALID` | state/version conflict | after re-read |
| `RESOURCE_EXHAUSTED` | `RATE_LIMITED`, `QUOTA_EXCEEDED` | limits | later |
| `DEADLINE_EXCEEDED` | `DEADLINE_EXCEEDED` | **may have completed** | see §8 |
| `UNAVAILABLE` | `NOT_READY`, `DEPENDENCY_DOWN` | temporary | reads: yes; mutations: see §8 |
| `UNIMPLEMENTED` | `UNSUPPORTED_PROTOCOL` | unknown method/major version | no |
| `INTERNAL` | `INTERNAL_ERROR` | unexpected; no details | no |

## 8. Idempotency and retries

- Read-only operations may be retried within the deadline policy.
- Mutating operations where duplicate execution is harmful accept an **idempotency key**; Core stores `(caller, key) → result` for a bounded time and returns the stored result on repetition.
- A timed-out request **may have completed**: the caller first queries state (by request/idempotency/job ID) before repeating.
- Publishing: Core never retries `Publish` automatically after a timeout, crash or `UNAVAILABLE` that occurred **after dispatch**; it sets `OUTCOME_UNKNOWN` and reconciles (ADR-0005 §5).
- The Gateway never silently replays non-idempotent calls after reconnect.

## 9. Health and readiness

Each process exposes `grpc.health.v1.Health` on its health socket: `SERVING` only when it is ready to accept work. The Watchdog distinguishes **process alive** (child exists), **ready**, **dependencies healthy** (Core reports DB status in its own health detail to authorized admins) and **application degraded** (some plugin not `READY`). Responses on health sockets carry status only. Detailed health (uptime, last success, consecutive failures, restart counts) is exposed to administrators via `WatchdogControl.ListProcesses` → Core → admin API.

## 10. Contract testing

- `buf lint` and `buf breaking` on every change to `proto/` (`buf breaking` runs against the previous release tag).
- Contract tests for every pair (web↔Gateway↔Core, Core↔plugin via Gateway) run in CI against the pinned versions in the release bundle.
- Negative tests: unauthenticated, wrong caller kind for a method, oversized message, expired deadline, unknown protocol version, forged `x-pfx-*` metadata, replayed/expired/wrong-plugin call token.
