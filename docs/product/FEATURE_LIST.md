# Feature List

**Revision 2 (2026-10-22).** Priorities: **P0** required foundation / release blocker; **P1** release capability; **P2** later enhancement; **P3** optional/future. Release tags: **[INFRA]** = Infra v0.1 (Phase A), **[IG]** = Instagram plugin v0.2 (Phase B), **[LATER]** = after v0.2. Status is planning-only. Milestone references point to `docs/development/ROADMAP.md`.

Technology baseline: ADR-0003 (C++20 server with validation gate, TypeScript/Fastify BFF, React/Vite frontend, PostgreSQL, Docker Compose, gRPC + Protocol Buffers).

## A. Deployment and operations

- **P0 [INFRA]** One documented Docker Compose deployment: `web`, `server`, `db`; optional `proxy` profile. *(M1, M12)*
- **P0 [INFRA]** Private internal network; only the web entry point published (default `127.0.0.1`); outbound-only `egress` network for the server. *(M1)*
- **P0 [INFRA]** Persistent volumes for database, media, plugin packages. *(M1)*
- **P0 [INFRA]** Health/readiness checks, structured logs, graceful shutdown in dependency order. *(M1, M3, M5)*
- **P0 [INFRA]** Version-pinned images; documented configuration; secrets generated by script and delivered as files. *(M1, M12)*
- **P0 [INFRA]** Hardened containers: read-only root filesystem, non-root where possible, dropped capabilities, `no-new-privileges`, resource limits. *(M1, M3)*
- **P1 [INFRA]** Backup/restore scripts with tested recovery (database + media + separate key handling). *(M12)*
- **P1 [INFRA]** Upgrade and rollback procedure including database migration rules. *(M12)*
- **P1 [INFRA]** Optional TLS reverse-proxy profile (Caddy). *(M12)*
- **P2 [LATER]** Optional S3-compatible media storage behind the storage interface.

## B. Users, roles and authorization

- **P0 [INFRA]** Secure initial admin creation via CLI (no default credentials). *(M6)*
- **P0 [INFRA]** Authentication, server-side sessions, logout, session expiry/rotation. *(M6)*
- **P0 [INFRA]** Admin can create, disable and manage users and roles. *(M6)*
- **P0 [INFRA]** Role-based authorization enforced server-side in Core. *(M6)*
- **P0 [INFRA]** Ownership enforced on every account, post, media, job, credential and plugin-data operation. *(M6+)*
- **P0 [INFRA]** Deny-by-default capability checks for plugin calls. *(M8, M9)*
- **P0 [INFRA]** Audit events for sensitive administrative, credential-lease and publishing actions. *(M5+)*
- **P1 [INFRA]** Password change/reset by admin; login rate limiting. *(M6)*
- **P2 [LATER]** Explicit delegation/sharing of resources between users, only if a defined use case requires it.
- **Constraint** Application admins have no implicit database superuser access and no implicit access to other users' content or credentials.

## C. Server process model

- **P0 [INFRA]** Watchdog as PID 1: process start order, restart with backoff, crash-loop detection, zombie reaping, signal forwarding, ordered shutdown. *(M3)*
- **P0 [INFRA]** Per-process UID, dropped capabilities, `no_new_privs`, rlimits, cleared environment, private temp dirs. *(M3)*
- **P0 [INFRA]** Secret distribution: per-process secret copies on tmpfs; plugin UIDs cannot read them. *(M3)*
- **P0 [INFRA]** Gateway: mTLS from web, per-plugin sockets, method allowlist, limits, deadlines, correlation IDs, caller identity assignment. *(M4)*
- **P0 [INFRA]** Independent health observation via per-process health sockets; aggregate Docker health with `DEGRADED` for plugin failures. *(M3, M5)*
- **P1 [INFRA]** Landlock/seccomp hardening for plugin processes where the kernel supports it. *(M8)*

## D. Plugin system

- **P0 [INFRA]** Versioned manifest, compatibility rules, strict validation (unknown fields rejected). *(M8)*
- **P0 [INFRA]** Plugin registry: status, version, hash-pinned executable, requested/granted capabilities, lifecycle state. *(M8)*
- **P0 [INFRA]** Plugin = native executable in its own process, own UID; no DB credentials, keys, Docker socket. *(M8)*
- **P0 [INFRA]** Operator CLI install (`postflowx-plugin install`), read-only plugin volume, hash verification at start. *(M8)*
- **P0 [INFRA]** Admin UI: review/grant capabilities, enable/disable, config, health, logs. *(M8, M11)*
- **P0 [INFRA]** Call tokens: user context only through Core-initiated calls. *(M9)*
- **P0 [INFRA]** Host API: storage (JSONB key/value), accounts, credentials (store/lease), media (stream/public URL), checkpoint, audit. *(M9)*
- **P0 [INFRA]** Declarative UI: descriptors with restricted JSON-Schema subset, rendered by the frontend. *(M9, M11)*
- **P0 [INFRA]** Callback and manifest-declared task mechanism invoked by Core. *(M9)*
- **P1 [INFRA]** Plugin SDK (C++), reference demo plugin with failure injection, test harness. *(M9)*
- **P1 [INFRA]** Uninstall with explicit data disposition (retain/export/delete). *(M8)*
- **P1 [INFRA]** Version switch with rollback to previous version. *(M8)*
- **P2 [LATER]** UI upload of plugin packages, signatures/provenance, staged updates, revocation, public catalog.
- **P2 [LATER]** Container-per-plugin isolation, egress filtering, strict credential mode (Core-side provider calls) for untrusted plugins.
- **P3 [LATER]** Iframe-based plugin UIs with narrow message bridge.
- **Constraint** A manifest is a declaration, not proof that code is safe; trust is a policy decision (bundled / operator-approved).

## E. Data and secrets

- **P0 [INFRA]** Core-owned `core` schema; migrations ordered, versioned, checksummed. *(M5)*
- **P0 [INFRA]** Least-privileged DB roles (runtime DML vs. migration DDL); `public` `CREATE` revoked; fixed `search_path`. *(M5)*
- **P0 [INFRA]** Credentials encrypted at rest (AEAD); master key outside the DB; `key_id` per ciphertext. *(M9)*
- **P0 [INFRA]** Only Core decrypts; plaintext only leaves Core as a lease to a granted plugin; never to browser/BFF. *(M9)*
- **P0 [INFRA]** Credential states (`ACTIVE`, `EXPIRING`, `EXPIRED`, `REVOKED`, `REAUTH_REQUIRED`), rotation of master key. *(M9, M12)*
- **P1 [INFRA]** Media upload validation (magic bytes, size limits), temp cleanup, quota policy. *(M9)*
- **P1 [INFRA]** Data export/deletion per user; clear uninstall retention semantics. *(M12)*

## F. Publishing and jobs

- **P0 [INFRA]** Posts: draft content, media references, target account, provider options. *(M11)*
- **P0 [INFRA]** Durable job state machine with attempts, leases, bounded retries, explicit terminal states. *(M10)*
- **P0 [INFRA]** Immediate and scheduled publishing with timezone-aware timestamps (UTC + IANA zone, DST policy, missed-window policy). *(M10)*
- **P0 [INFRA]** Idempotency keys and duplicate prevention. *(M10)*
- **P0 [INFRA]** Distinct handling of expired tokens, rate limits, transient and permanent errors. *(M10)*
- **P0 [INFRA]** Recovery after restart: never-dispatched attempts retry safely; dispatched attempts become `OUTCOME_UNKNOWN`. *(M10)*
- **P0 [INFRA]** `OUTCOME_UNKNOWN` + plugin `Reconcile`; user decision when undecidable. *(M10)*
- **P1 [INFRA]** Job history, user-facing error explanations, admin diagnostics. *(M10, M11)*
- **P2 [LATER]** Retry policy tuning, bulk operations, recurring schedules.

## G. Web application

- **P0 [INFRA]** Frontend + thin BFF; BFF forwards typed operations through the Gateway; no direct DB access. *(M7)*
- **P0 [INFRA]** Cookie/session handling with CSRF/origin protection; Core authoritative. *(M7)*
- **P0 [INFRA]** App shell, authentication views, navigation; degraded-state screen when the server is unavailable. *(M7)*
- **P0 [INFRA]** Admin UI: users, plugins, health. *(M7, M8, M11)*
- **P0 [INFRA]** User UI: accounts, composer (schema-driven provider options), media, jobs. *(M11)*
- **P0 [INFRA]** Generic OAuth callback route and public media route (token-validated by Core). *(M9, M11)*
- **P1 [INFRA]** Accessible validation/loading/error states, responsive layout. *(M11)*

## H. Instagram plugin (separate repository)

- **P0 [IG]** Verified prerequisites (account types, permissions, app review, media constraints, token lifetimes). *(M0.5, P0)*
- **P0 [IG]** OAuth connection, token storage and refresh via declared task. *(P1)*
- **P0 [IG]** Immediate publishing of the supported media type(s) with checkpoint/reconcile. *(P2)*
- **P0 [IG]** Scheduled publishing via platform jobs; error-class mapping; rate-limit handling. *(P3)*
- **P1 [IG]** Additional media types (carousel/reel) as permitted by the API. *(P3)*
- **P1 [IG]** No credentials in UI/logs; documented permissions and limits. *(P4)*

## I. Later plugins

- **P2 [LATER]** TikTok plugin after API feasibility.
- **P2 [LATER]** Further providers.

## J. Reliability, security and quality

- **P0 [INFRA]** Unit, integration, contract, authorization and deployment smoke tests; sanitizers in CI. *(M2+)*
- **P0 [INFRA]** Threat model and security acceptance tests (see `docs/security/THREAT_MODEL.md` §7). *(M13)*
- **P0 [INFRA]** Rate limits, request size limits, timeouts and bounded concurrency at Gateway/BFF/Core. *(M4+)*
- **P0 [INFRA]** Failure injection: plugin crash, Core crash mid-attempt, DB outage, Gateway outage. *(M13)*
- **P1 [INFRA]** Dependency and image scanning, SBOM, release provenance. *(M12/M13)*
- **P1 [INFRA]** Performance/load test against the stated baseline workload. *(M13)*
